## 2. 技術要件

- **Astro 5**（静的サイト生成）+ **TypeScript**
- **Tailwind CSS v4**
- 開発環境は WSL2 + VS Code。`pnpm` を使用
- **コンテンツはコンポーネントに直書きせず**、`src/data/*.ts` に構造化データとして分離する
  （メニュー6種、選ばれる理由3つ、流れ4ステップ、FAQ、導入事例などは全て配列データ化。
  非エンジニアが後から編集できるようにするため）
- 画像は `astro:assets` の `<Image>` で最適化（AVIF/WebP、`loading="lazy"`、
  FV画像のみ `loading="eager"` + `fetchpriority="high"`）
- JavaScript は最小限。アニメーションは IntersectionObserver + CSS のみ。フレームワークコンポーネント不要
- デプロイ想定：Cloudflare Pages（`npm run build` → `dist/` 静的出力）
- フォームバックエンドは持たない。初期は **メール（mailto）とLINEへの直リンク**でCVを受ける。
  将来の差し替えを想定し、CTAボタンは `<CtaButton>` コンポーネントに集約して置換1箇所で済むようにする

## 6. デザイン要件

### 6-1. 方向性
**「医療的な信頼感」×「サロンのやわらかさ」**。チラシは全面ピンクで情報密度が高いが、
Webでは**ピンクを面ではなく点として使い、余白と大きめのタイポで洗練させる**。
彩度の高いピンクの塗り面積は画面の10%以下に抑えること。

### 6-2. カラートークン（Tailwind v4 の `@theme` に定義）
```
--color-rose-brand:   #E0356B   /* チラシ準拠のアクセント。ボタン・数字・アイコンのみ */
--color-rose-deep:    #B72455   /* hover / 見出しの強調 */
--color-rose-tint:    #FDF2F6   /* セクション背景の淡色（面はこれを使う） */
--color-ink:          #1C1F23   /* 本文・見出し */
--color-ink-muted:    #5C6470   /* 補足テキスト */
--color-line:         #E8E6E7   /* 1px の罫線 */
--color-surface:      #FFFFFF
```
- 背景は白 `#FFFFFF` を基調に、セクションごとに `rose-tint` を交互に敷いてリズムを作る
- **クリーム・ベージュ系（#F5F5DC等）は使わない**
- グラデーションを使う場合は**同系色の色相差が小さいもののみ**（rose-tint → white 程度）。多色グラデ禁止

### 6-3. タイポグラフィ
- 日本語：`Noto Sans JP`（400 / 500 / 700）。Google Fonts、`display=swap` + `preconnect`
- 欧文・数字：`Figtree` または `Inter`。**料金の数字とセクション番号は必ず欧文フォント**でウェイトを効かせる
- 見出し `font-weight: 700`、`letter-spacing: -0.01em`、`line-height: 1.4`
- 本文 `line-height: 1.9`、`letter-spacing: 0.02em`（日本語は行間を広めに）
- H1 は clamp(2rem, 5vw, 3.5rem)。セクション見出しは clamp(1.5rem, 3.5vw, 2.25rem)
- **禁止：見出しの下にアクセントの下線バーを引くこと**（安っぽく見える）。区切りは余白で作る

### 6-4. レイアウト
- コンテンツ幅 `max-width: 1120px`、左右パディング 24px（SP 20px）
- セクション上下パディング：PC `128px`、SP `80px`。**余白をケチらない**
- 角丸は `16px` に統一（ボタンは `9999px` のピル型で1点だけ例外を作る）
- 影は `0 1px 2px rgba(0,0,0,.04), 0 8px 24px rgba(0,0,0,.06)` 程度に留める。多用しない
- カードの区切りは影より **1px の `--color-line`** を優先

### 6-5. モーション
- IntersectionObserver で `translateY(24px) → 0` + `opacity 0 → 1`、`400ms cubic-bezier(.16,1,.3,1)`
- 同一グリッド内は 60ms ずつ stagger
- **`@media (prefers-reduced-motion: reduce)` で全て無効化する**
- パララックスや大きな動きは使わない。Core Web Vitals を壊さない範囲で

### 6-6. レスポンシブ
- モバイルファーストで記述。ブレークポイントは `640 / 768 / 1024 / 1280`
- **主要な検証幅は 390px（iPhone）**。総務担当はスマホで一次確認する前提

## 7. 画像素材

`public/images/` に配置済み（別途zipで提供）。ファイル名と用途は同ディレクトリの `README.md` を参照。

- アイコンPNGは背景が白の透過なし。**可能なら lucide 等のSVGアイコンに置き換える**方が軽量で高品質。
  置き換えた場合は色を `--color-rose-brand` に統一
- 写真は `astro:assets` で AVIF/WebP 変換。FV画像は 1600px 幅、メニュー写真は 800px 幅を上限に
- **全画像に日本語の alt を付ける**（装飾目的のアイコンは `alt=""` + `aria-hidden="true"`）

## 8. 表現上の注意（必ず守る）

施術系サービスは景品表示法・医療広告規制まわりのリスクがあるため、以下を徹底：

- **「治る」「治療」「改善します」「効果があります」といった断定表現を使わない。**
  「〜が期待できます」「〜のケアをお手伝いします」に置き換える
- 医学的効果を保証する記述、疾患名を挙げて「治す」と示唆する記述を作らない
- 「No.1」「業界初」など**根拠のない優位性表現を勝手に作らない**
- 導入事例・お客様の声には必ず「※効果には個人差があります」を併記
- 数字を出す場合は必ず条件を添える（例：「2時間 22,000円〜（税込・出張費込み／遠方は別途）」）
- **チラシに書かれていない実績・社数・満足度などを創作しない**

※ これは法的助言ではないため、公開前に事業者側で表現の最終確認をする旨を `docs/open-questions.md` に明記すること。
